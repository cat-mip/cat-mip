# CAT-MIP MCP Server

This tool helps clarify ambiguous MSP and IT vocabulary, served as an MCP tool.
Send it any text and it returns the best-matching canonical CAT-MIP terms
with relevance scores — resolving ambiguous words like *account*, *device*,
*agent*, or *resource* before an AI acts on them.

> **Security note:** HTTP mode has no authentication and no protection
> against malicious calls. Run it locally or in a sandboxed environment
> only. Authentication can be added per your security guidelines but some
> assembly is required. 

---

## How it works

1. `build_flat_json.py` reads the YAML source files and writes
   `build/cat-mip-flat.json` — a flat list of `{ term, body }` objects
   where `body` is a single string containing definition, synonyms,
   relationships, examples, and agent actions.

2. On first start the server encodes every entry with `all-MiniLM-L6-v2`
   and persists the ChromaDB index to `scripts/mcp/cat-mip-chroma/`.
   Subsequent starts open the existing index — startup is near-instant.

3. The server exposes two MCP tools: `chroma_fetch` for semantic search
   and `chroma_peek` for index inspection.

4. If there is a a new version of CAT-MIP or you simply want to refresh
   the ChromaDB store, delete the contents of 
   /scripts/mcp/cat-mip-chroma

5. By default the server and client run on local stdio mode.  You can also 
   run them in http mode and select the port.  Both need to run using the 
   same command line arguements.
   Server Usage:
    python scripts/mcp/mcp_server.py         #stdio
    python scripts/mcp/mcp_server.py --http  #HTTP on port 8000

   Client Usage:
   # Start the server first:
    python scripts/mcp/mcp-server.py --http

   # Then in another terminal:
    python scripts/mcp/mcp-client.py "what should I do with the account?"
    python scripts/mcp/mcp-client.py "WMI" --n 5
    python scripts/mcp/mcp-client.py --peek
    python scripts/mcp/mcp-client.py --peek --limit 3
    python scripts/mcp/mcp-client.py --server http://remote-host:8000 "backup policy"

## Quick start

```bash
# 1. Clone
git clone https://github.com/cat-mip/cat-mip
cd cat-mip

# 2. Create and activate virtual environment
python -m venv .venv
source .venv/bin/activate        # macOS / Linux
# .venv\Scripts\activate         # Windows

# 3. Install dependencies
pip install -r scripts/mcp/requirements.txt

# 4. Build flat JSON from YAML source
python scripts/build_flat_json.py

# 5. Start the server (builds ChromaDB index on first run)
python scripts/mcp/mcp-server.py
```

For a full step-by-step walkthrough including VS Code debugger setup,
see [SETUP.md](SETUP.md).

## Running the server

```bash
# stdio — for Claude Desktop and local MCP clients (default)
python scripts/mcp/mcp-server.py

# HTTP — for the sample client, Gemini, or remote access
python scripts/mcp/mcp-server.py --http

# Custom port
python scripts/mcp/mcp-server.py --http --port 9000
```

The server uses **fastmcp 3.x** with `transport="http"`. The MCP endpoint
is at `/mcp`. On first start the ChromaDB index is built from
`build/cat-mip-flat.json` and persisted to `scripts/mcp/cat-mip-chroma/`.

> **Note:** sentence-transformers prints an `UNEXPECTED` warning on startup.
> This is benign — it occurs because `all-MiniLM-L6-v2` was trained for
> classification but is being used for embeddings.

## Using the sample client

With the HTTP server running in another terminal:

```bash
# Default query
python scripts/mcp/mcp-client.py

# Custom query
python scripts/mcp/mcp-client.py "what should I do with the account that is offline?"

# Acronym lookup
python scripts/mcp/mcp-client.py "WMI"

# More results
python scripts/mcp/mcp-client.py "backup and restore" --n 8

# Peek at the index
python scripts/mcp/mcp-client.py --peek
python scripts/mcp/mcp-client.py --peek --limit 10

# Remote server
python scripts/mcp/mcp-client.py "patch policy" --server http://your-server:8000
```

The client performs the MCP initialize handshake, captures the
`mcp-session-id` from the server response, and includes it in all
subsequent tool calls — as required by the fastmcp 3.x HTTP transport.

## Claude Desktop configuration

The server runs in **stdio mode** for Claude Desktop — no port needed.
Claude Desktop launches it as a child process automatically.

**macOS** — edit `~/Library/Application Support/Claude/claude_desktop_config.json`

**Windows** — edit `%APPDATA%\Claude\claude_desktop_config.json`

```json
{
  "mcpServers": {
    "cat-mip": {
      "command": "/full/path/to/cat-mip/.venv/bin/python",
      "args": ["/full/path/to/cat-mip/scripts/mcp/mcp-server.py"]
    }
  }
}
```

On Windows use `.venv\Scripts\python.exe` for the command path, and
use double backslashes or forward slashes in the paths.

Restart Claude Desktop after editing the config. The `chroma_fetch` and
`chroma_peek` tools will appear in the tools panel of any new conversation.

For  setup and detailed Claude troubleshooting see [SETUP.md](SETUP.md).

## Tools

### `chroma_fetch(text, n_results=5)`

Encodes incoming text with `all-MiniLM-L6-v2` and returns the top-matching
CAT-MIP canonical terms from ChromaDB. Use this to resolve ambiguous
MSP/IT vocabulary before acting on a prompt.

| Parameter   | Type   | Default  | Description                    |
|-------------|--------|----------|--------------------------------|
| `text`      | string | required | Text to disambiguate           |
| `n_results` | int    | 5        | Candidates to return (max 10)  |

```json
[
  {
    "term": "Tenant",
    "relevance_score": 0.8132,
    "body": "A Customer is an organization or individual that receives IT
services from an MSP. In technical terms, this is represented as a
Tenant -- a logically isolated environment within an MSP's management
system..."
  }
]
```

`body` is the full untruncated text — definition, synonyms, relationships,
example prompts, and agent actions concatenated into a single string.

### `chroma_peek(limit=5)`

Returns the first N documents from the ChromaDB collection. Primarily
used to verify the index loaded correctly and to inspect document structure.

| Parameter | Type | Default | Description                   |
|-----------|------|---------|-------------------------------|
| `limit`   | int  | 5       | Documents to return (max 10)  |

```json
{
  "total_docs": 78,
  "peek": [
    {
      "id": "0",
      "term": "Access Point",
      "body": "An Access Point is a network device that allows wireless..."
    }
  ]
}
```

`body` in peek results is truncated to 200 characters for readability.

## Embedding model

Both ingestion and queries use the same model — `all-MiniLM-L6-v2`.
Using different models for ingestion and query produces meaningless scores.

| Property | Value            |
|----------|------------------|
| Model    | all-MiniLM-L6-v2 |
| Dims     | 384              |
| Size     | ~90 MB           |
| License  | Apache 2.0       |

The model downloads once to `~/.cache/huggingface` on first run.
All subsequent use is fully local — no network calls at query time.

## Rebuilding after YAML changes

When new terms are added to `standards/accepted/` or `standards/draft/`:

```bash
# Regenerate flat JSON
python scripts/build_flat_json.py

# Delete the ChromaDB store to force a rebuild on next start
rm -rf scripts/mcp/cat-mip-chroma/    # macOS/Linux
# rd /s /q scripts\mcp\cat-mip-chroma  # Windows

# Restart the server — it will rebuild the index automatically
python scripts/mcp/mcp-server.py --http
```

## Verifying the server is running

```bash
# Check the port is open
lsof -i :8000            # macOS/Linux
netstat -ano | findstr :8000   # Windows

# Hit the MCP endpoint directly
curl -X POST http://localhost:8000/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"curl","version":"0.1"}}}'
```

A successful response returns a JSON object with
`"serverInfo": {"name": "cat-mip", "version": "3.x.x"}` and a
`mcp-session-id` response header.
